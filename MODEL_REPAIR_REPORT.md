# Исправление режима «почти всегда hold»

## Статус

**Техническая проблема воспроизведена и исправлена. Прибыльность не подтверждена;
допуска к реальной торговле нет.** Увеличение числа сигналов не считается
критерием прибыльной модели. Нельзя продолжать перебирать параметры на уже
увиденном test, пока случайно не получится положительный результат.

## Причины и изменения

1. Раньше лучшая эпоха выбиралась по F1 при фиксированных порогах 0.5. При
   нулевом F1 обучение останавливалось с checkpoint первой эпохи, хотя loss
   продолжал улучшаться. Python и C++ теперь выбирают минимум loss своего stage;
   scheduler использует то же направление оптимизации.
2. Validation разделён хронологически: первая половина для выбора эпохи,
   вторая для настройки порогов. Окна и горизонты целей не пересекают границу.
   Нормализация по-прежнему только из train. Даты сохранены в checkpoint.
3. Добавлена настройка порогов по фиксированной сетке из 81 пары без test.
   Есть минимальная поддержка, сравнение с постоянным классом и ограничение
   доли сигнальных окон. Отсутствие допустимого кандидата не создаёт checkpoint.
4. Первая версия критерия на calibration выбрала 98.9% сигнальных окон.
   Это вырождение, а не успешная модель. До новой оценки test добавлено
   ограничение доли сигналов <=50%. Обе версии отчёта сохранены; это разработка
   на validation, поэтому её метрики нельзя выдавать за независимую оценку.
5. `load_checkpoint()` восстанавливает пороги для прямого `detect_patterns()`.
   Раньше прямой вызов без аргументов мог вернуться к 0.5, даже если backtest
   использовал настроенные пороги. Явные аргументы по-прежнему имеют приоритет.
6. Warm-start запрещён при смене зарезервированной calibration-части и из уже
   откалиброванного checkpoint. Добавлены проверки схемы порогов, checksum
   исходных данных, тесты вырожденных прогнозов и сравнение Python/C++.

## Данные и эксперимент

- BTCUSDT, spot + futures, 1h, 8760 закрытых свечей.
- История: 2025-09-07 22:00 UTC — 2026-09-07 22:00 UTC, правая граница исключена.
- CSV: `data/btcusdt_1h_20250907_20260907/market.csv`.
- SHA-256: `d947ea98edfd39a1b94abbccb8930403000ad83cc369150fe40ab02c1da3876d`.
- OI отсутствует последовательно; OI-паттерны не получают обучающих примеров.
- Train: 5997 окон, 893 окна с событиями. Selection: 622 окна / 80 событий.
  Calibration: 622 окна / 72 события. Test: 1279 окон / 137 событий.
- Новый запуск: C++/LibTorch, 20 эпох, seed 42, lr 0.0003, seq_len 32,
  horizon 4, dim 32, states 16, layers 1, batch 64, один поток, с нуля.
- Выбрана эпоха 20. Обучение эпох заняло 389.23 s, validation — 8.02 s;
  подготовка CSV, конверсия и последующие проверки не входят в эти времена.
- Пороги финального экспериментального checkpoint: gate 0.2, conditional 0.5,
  joint confidence 0.0. Calibration: 130/622 сигнальных окон, 9 правильных
  strongest-pattern прогнозов, F1 0.0891 против 0.0836 постоянного класса.
  Это слабое преимущество, не статистическое доказательство торговой полезности.

## Исторический test: до / после

**Это диагностический период, уже просмотренный в предыдущем эксперименте.**
Первый вход: 2026-07-16 12:00 UTC. Последняя целевая свеча: 2026-09-07 21:00 UTC.
Таким образом, прежняя одна сделка относилась примерно к 54 дням, а не ко всему году.

| Показатель | Первый запуск | После исправлений |
|---|---:|---:|
| Сигнальные окна при независимом прогнозе каждого окна | 1 | 252 |
| Завершённые сделки | 1 | 135 |
| Event recall | 0.73% | 23.36% |
| Event precision | 100% при одном прогнозе | 12.70% |
| Gate average precision | 0.1246 | 0.1534 |
| Gate ROC AUC | 0.5482 | 0.5833 |
| Итог капитала | $9,989.69 | $9,460.80 |
| Доходность после комиссий | -0.103% | -5.392% |

В новом запуске точный strongest-pattern оказался верным в 17 из 252 сигнальных
окон (6.75%). Event precision проверяет наличие любого события, а не правильность
направления или прибыльность сделки. Нельзя путать эти показатели.

252 окна не равны 252 сделкам: backtest не открывает новые позиции во время
уже открытой позиции. Его счётчик сигналов содержит только рассмотренные входы.

Фиксированные условия backtest: старт $10,000, размер 20% капитала, комиссия
0.1% с каждой стороны, long/short, SL 1%, TP 2%, максимум 4 свечи, stop-first,
cooldown 1. Без динамического размера, внешнего gate, slippage, funding и borrow.

- 84 long / 51 short; win rate 32.59%; profit factor 0.4941.
- Максимальная просадка 5.43%; комиссии $524.59.
- Чистый PnL -$539.20; без записанных комиссий приблизительно -$14.61.
- Следовательно, увеличение оборота не создало преимущества после издержек.
- Рост самой цены на этом интервале +23.20% не является сопоставимым по риску
  эталоном для стратегии с 20% размером позиции и непостоянной экспозицией.

## Простые baseline

Оба baseline обучены только на train, параметры зафиксированы. Признаки:
последнее значение, среднее, стандартное отклонение, разность первого и
последнего значений в том же причинном окне. Это baseline обнаружения событий,
не самостоятельные торговые стратегии.

| Gate AP | Selection | Calibration | Diagnostic test |
|---|---:|---:|---:|
| Частота событий / постоянный score | 0.1286 | 0.1158 | 0.1071 |
| Toric | 0.1726 | 0.1696 | 0.1534 |
| Logistic regression | 0.1844 | 0.1380 | 0.1481 |
| Histogram gradient boosting | 0.1751 | 0.1568 | 0.1503 |

У Toric есть некоторое ранжирование событий, но убедительного преимущества
сложной архитектуры над простыми моделями и прибыльной торговли не показано.

## Воспроизведение

Запускать из корня с установленным проектом в `.venv` и собранным C++ binary.
Для повторного запуска выбирать новую директорию, не перезаписывать артефакты.

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
.venv/bin/python toric_markov_model/scripts/train_trading_cpp.py \
  --data data/btcusdt_1h_20250907_20260907/market.csv \
  --seq-len 32 --prediction-horizon 4 --dim-angles 32 --num-states 16 \
  --num-layers 1 --batch-size 64 --threads 1 --epochs 20 \
  --early-stop-patience 5 --lr 0.0003 --checkpoint-dir checkpoints_reproduce
.venv/bin/python toric_markov_model/scripts/calibrate_trading.py \
  --data data/btcusdt_1h_20250907_20260907/market.csv \
  --checkpoint checkpoints_reproduce/best_model_stage0.pt \
  --output checkpoints_reproduce/calibrated_selective_stage0.pt
.venv/bin/python toric_markov_model/scripts/diagnose_trading.py \
  --data data/btcusdt_1h_20250907_20260907/market.csv \
  --checkpoint checkpoints_reproduce/calibrated_selective_stage0.pt \
  --output checkpoints_reproduce/diagnostics.json --include-test
.venv/bin/python toric_markov_model/scripts/backtest_trading_v3.py \
  --data data/btcusdt_1h_20250907_20260907/market.csv \
  --checkpoint checkpoints_reproduce/calibrated_selective_stage0.pt \
  --split test --position-size 0.2 --transaction-cost 0.001 --max-hold-bars 4 \
  --stop-loss 0.01 --take-profit 0.02 --enable-short \
  --output checkpoints_reproduce/test_backtest.csv
.venv/bin/python -m unittest discover -s toric_markov_model/tests -t toric_markov_model -v
```

## Артефакты и ограничения

Проверка после всех изменений: **45 тестов прошли**, включая native/Python
паритет, выбор checkpoint, резервирование calibration, сохранённые пороги
инференса и сквозной train/calibrate/backtest. `compileall` и `git diff --check`
завершились без ошибок. Лог тестов: `checkpoints_btc_year_run2/tests.log`.

В `checkpoints_btc_year_run2/` находятся протокол, native-логи, веса, calibration
JSON, `diagnostics.json`, CSV портфеля/сделок и `test_backtest_metrics.json`.
Использованный экспериментальный checkpoint — `calibrated_selective_stage0.pt`.
**Не использовать `calibrated_model_stage0.pt`: это отвергнутый почти
always-active кандидат, сохранённый для аудита.** Ни один из них не одобрен для
реальной торговли; в финальном calibration-отчёте `production_approved: false`.

Остаются исследовательские задачи, а не известные исправимые ошибки исполнения:
подтверждение преимущества после всех издержек, оценка по нескольким причинным
walk-forward периодам и совершенно новые данные после заморозки решения.
Результат на уже просмотренном test нельзя улучшать перебором и затем называть
независимой проверкой. Торговля реальными средствами не запускалась.
